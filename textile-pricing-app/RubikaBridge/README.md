# راهنمای روبیکا

نسخهٔ فعلی فقط از ربات رسمی استفاده می‌کند. راهنمای معتبر راه‌اندازی در
[BOT-SETUP.md](BOT-SETUP.md) است. تولید PDF چاپی A4 نام مشتری، نوع پرداخت و وضعیت
ارزش افزوده را نمایش نمی‌دهد؛ محاسبهٔ قیمت اختصاصی مشتری همچنان حفظ شده است.

مطالب زیر صرفاً سابقهٔ اتصال قدیمی‌اند؛ ورود و ارسال با حساب شخصی در برنامه
و bridge غیرفعال شده‌اند. مراحل حساب شخصی را اجرا نکنید.

## سابقهٔ اتصال حساب شخصی (غیرفعال)

این اتصال غیررسمی است، از Bot API استفاده نمی‌کند و پایداری آن تضمین‌شده نیست.
فقط حساب متعلق به خودتان و مشتریانی که انتظار پیام دارند را به کار ببرید.
شمارهٔ مشتری ممکن است به مخاطبان حساب اضافه شود. ارسال موفق یعنی روبیکا شناسهٔ
پیام برگردانده است، نه اینکه مشتری آن را دریافت یا خوانده باشد.

## نصب روی سرور

Python 3.12 یا جدیدتر، دسترسی خروجی HTTPS به سرویس‌های روبیکا و GitHub/PyPI لازم است.
از ریشهٔ پوشهٔ منتشرشدهٔ برنامه در PowerShell:

```powershell
python -m venv App_Data/rubika-venv
App_Data/rubika-venv/Scripts/python.exe -m pip install -r RubikaBridge/requirements.txt
```

در لینوکس:

```sh
python3 -m venv App_Data/rubika-venv
App_Data/rubika-venv/bin/python -m pip install -r RubikaBridge/requirements.txt
```

نسخهٔ سورس کتابخانه به commit مشخصی ثابت شده است. کل محیط پایتون را بین ویندوز
و لینوکس کپی نکنید؛ آن را روی سرور نصب کنید. در صورت استفاده از مسیر دیگر،
تنظیم محیطی `Rubika__PythonPath` را به مسیر کامل python تنظیم کنید.
این محیط جداگانه در خروجی self-contained دات‌نت بسته‌بندی نمی‌شود.

## راه‌اندازی

1. با مدیر سیستم به صفحهٔ تنظیمات بروید؛ شمارهٔ حساب ارسال‌کننده را وارد کنید.
2. «دریافت کد ورود» و سپس تأیید کد. رمز دومرحله‌ای فقط در صورت نیاز وارد شود.
   اگر روش ورود یا رمز دومرحله‌ای در حساب شما توسط سرویس پذیرفته نشد، ارسال
   فعال نمی‌شود؛ سازگاری واقعی نیاز به تست حساب دارد.
3. شمارهٔ موبایل مشتری‌ها و ارتباط کالا/مشتری را ذخیره کنید.
4. «ارسال قیمت برای مشتریان» پیش‌نمایش PDF قیمت اعتباری ریالی اختصاصی، با/بدون
   ارزش افزوده و مشتری‌های فاقد موبایل معتبر را نشان می‌دهد. تا تأیید نکنید
   هیچ پیام ارسال نمی‌شود. پیش‌نمایش بعد از ۱۰ دقیقه منقضی می‌شود.
5. برای تست نخست، فقط یک مشتری آزمایشی با یک کالا داشته باشید.

## امنیت، صف و استقرار

خطاها همراه با مرحله، نوع خطا و کد پیگیری نمایش داده می‌شوند. گزارش امن در
`App_Data/rubika-diagnostics.jsonl` و لاگ برنامه ثبت می‌شود؛ فقط زمان، کد پیگیری،
نوع/مرحلهٔ خطا، وضعیت HTTP و نام کلاس خطا از فهرست مجاز ثبت می‌شوند. شماره، OTP،
رمز دومرحله‌ای، نشست، متن پیام و پاسخ خام روبیکا ثبت نمی‌شوند. گزارش بیش از یک
مگابایت به `.previous` منتقل می‌شود. برای خطای قدیمی، باید درخواست بعدی را خودتان
از صفحه اجرا کنید تا کد پیگیری جدید تولید شود.

- نشست و درخواست ورود در `App_Data/rubika-account.protected` با Data Protection
  رمزگذاری می‌شوند؛ OTP/رمز/نشست در خط فرمان، HTML یا لاگ‌ها نمایش داده نمی‌شوند.
  کلیدهای `App_Data/Keys` برای بازیابی نشست لازم‌اند؛ از کل پوشه بک‌آپ امن بگیرید.
- حساب سرویس فقط به App_Data دسترسی لازم داشته باشد. این پوشه، بانک قیمت‌ها،
  کلیدها و فایل‌های پایتون را در وب منتشر نکنید. سایت مدیریتی باید HTTPS داشته باشد.
- فقط مدیر سیستم حساب ارسال‌کننده را مدیریت می‌کند. ارسال نیاز به دسترسی ویرایش
  صفحهٔ ارتباط کالا/مشتری و توکن ضد جعل دارد.
- فقط **یک نمونهٔ برنامه/worker** با این بانک داده اجرا شود؛ web garden یا چند
  replica فعال نکنید. در IIS برای ارسال طولانی، برنامه باید همیشه فعال باشد.
- متن قیمت‌ها در زمان پیش‌نمایش ثابت می‌شود؛ ارتباط‌های ذخیره‌نشده ارسال نمی‌شوند.
  شمارهٔ تکراری بین مشتریان مانع شروع ارسال است. شمارهٔ نامعتبر با اعلام به کاربر
  کنار گذاشته می‌شود. برای هر مشتری یک PDF با فونت وزیرمتن (مجوز OFL همراه فونت)
  ساخته می‌شود؛ نام شرکت را در تنظیمات وارد کنید. هدر سند و عنوان ستون‌های جدول
  در هر صفحه تکرار می‌شوند. فاصلهٔ ارسال‌ها ۵ ثانیه است.
- درصد افزایش/کاهش برابر `(قیمت جدید - قیمت قبلی) / قیمت قبلی * 100` است؛ مبنا
  آخرین **PDF ارسال موفق** همان کالا برای همان مشتری، با مالیات/معافیت و تخفیف
  اختصاصی است. اولین ارسال یا قیمت قبلی صفر با `-` مشخص می‌شود. سابقهٔ نسخه‌های
  قدیمی متنی مبنا نیست. PDF و قیمت مبنا هنگام پیش‌نمایش ثابت‌اند و سابقه فقط بعد
  از دریافت شناسهٔ پیام موفق از روبیکا، در همان تراکنش ثبت موفقیت، به‌روز می‌شود.
- دانلود PDF در پیش‌نمایش فقط برای کاربر دارای دسترسی ویرایش صفحهٔ ارتباط است؛
  فایل‌ها از بانک داده ارائه می‌شوند، در wwwroot قرار نمی‌گیرند و no-store هستند.
- وضعیت هر پیام و شناسهٔ روبیکا در جدول‌های RubikaDispatches/RubikaDispatchItems
  ثبت می‌شود. «آخرین ارسال موفق» تاریخ شمسی و ساعت/دقیقهٔ تهران است.
- خطای محدودیت/ورود/شبکه صف را متوقف می‌کند؛ هیچ تلاش خودکار مجدد انجام نمی‌شود.
  ارسال در حال انجام هنگام قطع برنامه «نامشخص» و باقی صف «متوقف» می‌شود.
  قبل از ارسال دوباره، نتیجه را در روبیکا بررسی کنید تا پیام تکراری نرود.
- «قطع اتصال» نشست محلی را حذف می‌کند؛ برای لغو نشست روبیکا، از داخل نرم‌افزار
  روبیکا هم دستگاه مربوطه را خارج کنید.
- برای Release پروژه، روال امضای SecurePublish موجود را حفظ کنید؛ این تغییر
  حفاظت لایسنس/یکپارچگی را غیرفعال نمی‌کند.

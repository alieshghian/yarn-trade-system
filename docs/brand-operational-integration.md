# اتصال فرم سه‌فیلدی برند

## قرارداد قاب فرم عملیاتی

عنوان عملیاتی «تعریف برند» است. تنظیمات کاربر، حالت انتخاب با موس و دستگیره‌های قاب را فعال می‌کند. پنل قلم `DesignerFontPanel` مستقیماً از پنل آزمایشگاه استخراج و در هر دو مسیر استفاده می‌شود؛ رنگ از `ExcelColorPicker` و ژست اندازه از helper مشترک Designer می‌آید. تغییرات هر فیلد/برچسب به‌صورت override شخصی ذخیره می‌شوند. عرض ذخیره‌شدهٔ نوار جدول در نمایش به عرض موجود محدود می‌شود، بدون بازنویسی JSON طراحی.

قاب مشترک `OperationalFormFrame` ارتفاع ثابت (پیش‌فرض ۷۶۰ پیکسل یا ارتفاع صریح طراحی/کاربر) دارد. تعداد رکورد، جست‌وجوی خالی و عملیات ثبت اندازهٔ قاب را تغییر نمی‌دهند؛ اسکرول داخل فضای جدول انجام می‌شود، حاشیهٔ داخلی افقی جدول در هر دو طرف ۱۲ پیکسل است و footer در پایین قاب باقی می‌ماند. اندازه فقط با تنظیم صریح مجاز کاربر تغییر می‌کند.

پیام خالی از جریان صفحه حذف می‌شود تا میان نوار عنوان و پنل ورود فاصله نیفتد. عرض هر ستون و ارتفاع سرستون/نوار ابزار در ذخیره‌سازی شخصیِ همان حساب و همان فرم نگهداری می‌شود؛ در حالت تنظیمات با «ذخیره» ثبت و با «خروج بدون ذخیره» کنار گذاشته می‌شود و در حالت عادی پس از پایان کشیدن فوراً ذخیره می‌شود. راست‌کلیک یا جابه‌جایی میان فرم‌ها نباید انتخاب روش جست‌وجو را تغییر دهد؛ گروه دکمه‌های رادیویی هر جدول مستقل است و گزینهٔ فعال، هم دایرهٔ انتخاب‌شده و هم تأکید نوشتاری پررنگ دارد.

قرارداد رفتار قابل استفادهٔ مجدد در `frontend/src/components/base-form/laboratoryOperationalBehavior.json` نگهداری می‌شود و خروجی‌گیر Designer کل قرارداد را داخل JSON هر فرم قرار می‌دهد. قاب عملیاتی از همین snapshot هدف‌های قابل‌قالب‌بندی و قواعد راست‌کلیک را می‌خواند؛ مجوزهای رنگ و قلم شامل عنوان/هدر فرم، پنل و پیام فرم، همهٔ اجزای نوار جدول (جست‌وجو و گزینه‌هایش)، زمینهٔ جدول، سرستون‌ها، ردیف‌ها و داده‌های ستون است. عنوان قابل قالب‌بندی است اما جابه‌جا نمی‌شود. راست‌کلیک از گروه‌های منوی آزمایشگاه و همان `DesignerFontPanel` و `ExcelColorPicker` استفاده می‌کند. نشان فوکوس فیلد در حالت ورود با blur پاک نمی‌شود و با فوکوس فیلد دیگر جابه‌جا می‌شود؛ ذخیره یا خروج آن را پاک می‌کند.

دکمهٔ تنظیمات در نوار بالا قرار دارد. مجوزهای `customization.colors` و `customization.typography` همهٔ هدف‌های ظاهری قرارداد را کنترل می‌کنند؛ `tablePresentation` همچنان فقط برای عملیات ارائه‌ای/ساختاری جدول است و مانع رنگ یا قلم نمی‌شود. تنظیمات شخصی با کلید حساب و شناسهٔ فرم در فضای جداگانهٔ مرورگر ذخیره می‌شوند؛ سند طراحی و قالب مادر تغییر نمی‌کنند. تمام فرم‌های عملیاتی جدید یا جایگزین باید از این قاب و snapshot قراردادی JSON استفاده کنند؛ این الزام در `AGENTS.md` ثبت شده است.

- مسیر اصلی `brands` و ایجاد برند از فرم اشخاص، همان `BrandsPage` را صدا می‌زنند. نمایش پیش‌فرض آن اکنون `DesignedBrandsView` است؛ API، شناسه رکورد، مجوزها، `rowVersion` و رویداد `brands-changed` حفظ شده‌اند.
- مرجع عیناً از خروجی مالک به `frontend/src/forms/brand-design.json` کپی شده است. شناسه: `form.redesign.805deb77-bec5-41fa-af97-77b7007ca3a4`. SHA256: `6C2F801D8076D73007E31F5999CC588D8CB77C7A40BDB6365F5A82115CFF543F`.
- هیچ هندسه‌ای در JSON بازنویسی نمی‌شود. در Adapter فقط عنوان «شخص جدید» به «برند جدید» اصلاح می‌شود. سه ستون به `brandCode`, `brandName`, `description` متصل‌اند؛ شناسه داخلی فیلد توضیحات همچنان `brandDescription` است.
- آدرس در Draft کامل باقی می‌ماند و هنگام PUT ارسال می‌شود، هرچند در فرم دیده نمی‌شود. قالب مادر، تاریخچه و داده‌های محلی Designer دست‌کاری نمی‌شوند.
- کد از موتور مشترک `serialCode` استفاده می‌کند. ارقام فارسی استاندارد می‌شوند؛ بزرگی/کوچکی حروف در ذخیره حفظ و در مقایسه نادیده گرفته می‌شود. پیشنهاد `/api/sequence-suggestions/brand` از آخرین زمان ایجاد می‌آید؛ برخورد با کد موجود، ورود دستی می‌خواهد و شماره رزرو نمی‌کند.
- برای جلوگیری از رقابت کدهای متفاوت از نظر بزرگی حروف، Create/Update برند در SQL Server زیر قفل تراکنشی `sp_getapplock` اجرا می‌شوند؛ ایندکس یکتای موجود نیز باقی است. این قرارداد برای نوشتن از API است؛ نوشتن مستقیم بیرون API تابع محدودیت‌های خود دیتابیس است. Migration جدیدی وجود ندارد.
- تنها افزودنی مشترک، ورودی اختیاری `selectedRowId` جدول است تا انتخاب رکورد پس از ذخیره با پنل بالا هماهنگ بماند؛ مصرف‌کنندگان قبلیِ بدون این ورودی تغییری ندارند.

## بازگشت

متغیر محیطی `VITE_BRANDS_FORM=legacy` را برای فرانت‌اند تنظیم و سرور توسعه را با `runapp2.bat` دوباره اجرا کنید. در انتشار production این متغیر هنگام ساخت تنظیم می‌شود. حذف این تنظیم، نمایش سه‌فیلدی را برمی‌گرداند. این انتخاب به رکوردهای دیتابیس یا فرم آزمایشگاهی دست نمی‌زند.

## بررسی‌های انجام‌شده

- TypeScript: `npx tsc --noEmit -p tsconfig.app.json`.
- تست مستقیم Backend: فیلتر `FullyQualifiedName~Brand&FullyQualifiedName!~Brand_SQL`؛ تست‌های SQL و Migration اجرا نشده‌اند.
- ۵۹ تست موتور کد و renderer مشترک؛ ۱۴ بررسی مرورگری محدود در `tests/brands-operational.browser.mjs` با API ساختگی و پروفایل موقت، شامل تطابق مختصات با مرجع واقعی آزمایشگاه، CRUD، جست‌وجو، F3، آدرس مخفی، نسخه، مجوز و callback ایجاد از اشخاص.
- مسیر قفل SQL Server در تست InMemory اجرا نمی‌شود؛ تأیید SQL هم‌زمانی با دیتابیس آزمایشی، قبل از انتشار production لازم است. عملیات واقعی روی داده‌های مالک برای تست انجام نشده است.

برای اجرای API محلی بدون تغییر داده در راه‌اندازی، متغیرهای `Database__AutoMigrate=false` و `Seed__Enabled=false` به فرایند `runapp1.bat` داده می‌شوند. Build کامل فرانت‌اند و تست گسترده فرم‌ساز برای این اتصال اجرا نشده است.

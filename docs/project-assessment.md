# ارزیابی وضعیت پروژهٔ سامانهٔ بازرگانی نخ امانی

> این سند بر پایهٔ بررسی ایستای سورس موجود در `C:\project\yarn-trade-system` و دو آرشیو تحویل در `C:\project zip` تهیه شده است. این سند گزارش اجرای آزمون تازه نیست.

## خلاصهٔ اجرایی

پروژه یک سامانهٔ یکپارچهٔ بازرگانی برای خرید و واردات نخ امانی، موجودی، فروش، دریافت‌وپرداخت، چک و حساب شرکا است. اسکلت فنی و بخش بزرگی از جریان‌های اصلی در سورس پیاده‌سازی شده‌اند: API مبتنی بر ASP.NET Core و EF Core، رابط React/TypeScript، مدل داده و migrationها، مجوزها، دادهٔ نمونه و آزمون‌های واحد.

در وضعیت فعلی، رابط کاربری در حالت نمایشی قابل مشاهده است. ورود واقعی از کار افتاده بود چون API محلی بالا نیامد: محیط فعلی فقط .NET 10 runtime دارد، برنامه به .NET 8 نیاز دارد و بازیابی یک بستهٔ NuGet نیز با خطای TLS/اعتبارسنجی مواجه شد. به همین دلیل وضعیت اجرایی end-to-end، اتصال به SQL Server و ورود واقعی هنوز تأیید نشده‌اند.

## آنچه در سورس دیده می‌شود

### معماری و فناوری

- یک modular monolith شامل ASP.NET Core 8 Web API، SQL Server و رابط React 19 / TypeScript / Vite است.
- EF Core، ASP.NET Core Identity، نقش‌ها و مجوزهای عملیاتی در API استفاده شده‌اند.
- ساختار کد API شامل کنترلرهای اشخاص و اطلاعات پایه، سفارش خرید، خرید، فروش، مالی، گزارش، پیوست، کاربران، تنظیمات، حضور کاربر و کارتابل است.
- مدل دامنه، DbContext، seeder، سرویس‌های محاسبات تجاری، ثبت قطعی اسناد، مقایسهٔ خرید و واردکنندهٔ XLSX در سورس وجود دارند.
- در پوشهٔ migrationها، migration اولیه و چندین تغییر بعدی برای اشخاص، نخ، سفارش خرید، دسترسی کاربران، کارتابل، تنظیمات و حضور/اعلان نگهداری دیده می‌شود.

### قابلیت‌های اصلی موجود

- مدیریت اشخاص، نقش‌های کاری، کاربران، مجوزها، نخ، انبار و تنظیمات کاربر.
- سفارش خرید نخ و گردش کار کارتابل نقش‌ها.
- فاکتور خرید، هزینه‌های واردات، تخصیص هزینه و ورود اطلاعات Excel برای invoice و packing list.
- گردش موجودی و لایه‌های بهای تمام‌شده با روش‌های FIFO، LIFO و میانگین وزنی.
- فروش نقدی و اعتباری، برنامهٔ پرداخت و محدودیت اعتبار.
- دریافت و پرداخت چندردیفی، چک و تغییر وضعیت کنترل‌شده.
- حساب و تسویهٔ شرکا با پشتیبانی ارزهای IRR و USD، پیوست، audit و گزارش‌ها.
- رابط دوزبانهٔ فارسی/انگلیسی و کنترل‌های تاریخ شمسی/میلادی.

این فهرست وجود ساختار و کدهای مرتبط را خلاصه می‌کند؛ به‌تنهایی به معنی تأیید همهٔ سناریوها در اجرای واقعی نیست.

## آرشیوهای دریافت‌شده

- `api.zip` حاوی خروجی انتشار API است: DLLها، فایل‌های runtime/config و رابط منتشرشده در `wwwroot`. در آن فایل‌های سورس `.cs` یا پروژهٔ `.csproj` نیست. بنابراین این آرشیو برای اجرای خروجی منتشرشده مفید است، اما جای سورس API را نمی‌گیرد.
- `implementation-summary.zip` حاوی `implementation-summary.md` است. این خلاصه ادعا می‌کند ۲۰ آزمون، build فرانت‌اند/بک‌اند و نمونه‌های Excel بررسی شده‌اند. این نتایج را در این بررسی دوباره اجرا نکرده‌ام.
- سورس قابل تحلیل از قبل در `C:\project\yarn-trade-system` موجود است؛ فرانت‌اند، API، تست‌ها و مستندات همان‌جا هستند. فایل‌های خروجی مانند `frontend/dist` و `bin/obj` نیز کنار سورس دیده می‌شوند.
- خلاصهٔ تحویل به migration اولیه اشاره می‌کند، اما سورس فعلی migrationهای بیشتری دارد؛ برای ادامه باید خود سورس و تاریخچهٔ migrationها مرجع باشند.

## وضعیت اجرا و موانع فعلی

1. فرانت‌اند با `?demo=1` و دادهٔ نمایشی باز می‌شود؛ این حالت اتصال مجاز به API ایجاد نمی‌کند.
2. Vite در تنظیم فعلی، مسیرهای `/api` و `/health` را به `http://localhost:5223` هدایت می‌کند. ورود واقعی به بالا بودن API روی همین مقصد نیاز دارد.
3. API برای `net8.0` ساخته شده است. روی محیط فعلی .NET SDK 10 دیده می‌شود و .NET 8 runtime در فهرست runtimeهای نصب‌شده نیست.
4. اجرای build به بازیابی packageای NuGet نیاز دارد که در اجرای قبلی به خطای TLS/اعتبارسنجی خورد؛ اجرای `--no-restore` هم به دلیل package cache ناقص موفق نشد.
5. SQL Server سرویس محلی فعال است، اما اجرای migration و اتصال برنامه به دیتابیس در این بررسی تأیید نشده است. خلاصهٔ تحویل نیز محدودیت TLS/Force Encryption برای SQL Server را ثبت می‌کند.
6. فولدر پروژه در مسیر فعلی metadata مخزن Git قابل‌مشاهده نداشت؛ در نتیجه وضعیت تغییرات نسخه‌بندی‌شده و commit پایه مشخص نیست.

## پیشنهاد مرحله‌بندی ادامهٔ تحلیل و توسعه

### اولویت ۱: تثبیت اجرای محلی

- تعیین نسخهٔ هدف runtime و فراهم‌کردن .NET 8 runtime/SDK سازگار یا انتشار self-contained.
- رفع دسترسی NuGet و بازیابی dependencyها از منبع قابل‌اعتماد.
- مشخص‌کردن instance، نام دیتابیس، سیاست TLS و Connection String محیط توسعه.
- اجرای API، بررسی health/Swagger، اعمال migration و آزمون ورود واقعی با دادهٔ seed.
- یکسان‌سازی پورت فرانت‌اند، CORS و مقصد proxy تا اجرای مجدد روی پورت دیگری مثل 5174 ورود را خراب نکند.

### اولویت ۲: بازبینی کسب‌وکار و صحت داده

- ترسیم سناریوهای انتهابه‌انتها برای سفارش خرید تا دریافت کالا و ثبت موجودی، و برای فروش تا دریافت وجه و تسویهٔ شریک.
- تطبیق محاسبات وزن، هزینهٔ واردات، بهای تمام‌شده، ارز، اعتبار، سررسید و سهم سود با قواعد مورد تأیید کسب‌وکار.
- بررسی رفتار reversal/adjustment، تکرارپذیری posting، هم‌زمانی و تراکنش‌ها تا ثبت دوباره یا ماندهٔ ناسازگار رخ ندهد.
- کنترل واردکننده با فایل‌های واقعی و تعریف روشن موارد نیازمند تأیید اپراتور.

### اولویت ۳: امنیت و عملیات

- حذف رمز پیش‌فرض توسعه از هر محیط غیرآزمایشی و انتقال secretها به configuration امن.
- بررسی مجوزها روی API، حفاظت فایل‌های پیوست، audit، backup/restore و راهبرد نگهداری داده.
- تعریف استقرار، logging، مانیتورینگ، migration عملیاتی و بازیابی از خطا.

### اولویت ۴: تجربهٔ کاربری و پوشش آزمون

- مرور صفحه‌به‌صفحه با کاربران، ثبت موارد ناقص/نامفهوم و تعیین اولویت محصول.
- تکمیل آزمون‌های API و جریان‌های یکپارچه کنار آزمون‌های محاسباتی؛ تعیین دادهٔ مرجع برای تطبیق مالی.
- تأیید کیفیت دو زبانه، RTL/LTR، ورودی تاریخ، جدول‌های طولانی و اندازه‌های صفحه.

## گام بعدی پیشنهادی

تحلیل بعدی را از مرور فایل‌های API و رابط در کنار هم شروع کنیم و برای هر جریان اصلی یک جدول «قابلیت موجود / شاهد در کد / نیازمند تأیید / کار بعدی» بسازیم. پس از تثبیت اجرای API، همین جدول را با رفتار واقعی و دادهٔ نمونه تکمیل کنیم.

# اولویت‌بندی اصلاحات هستهٔ عملیاتی Yarn Trade

**این سند برنامه است، نه مجوز اجرا.** راهکار محصولی فقط یک سیستم عملیاتی دائمی با تاریخ مؤثر واقعی است؛ historical mode، زیرسیستم recovery، یا ledger موازی ساخته نشود. هر آزمون/تمرین قبل از اتصال به DB عملیاتی روی disposable SQL انجام شود.

## Owner decisions still required

Before P0 schemas encode behavior, decide source of truth for actual receipt date/time and same-day order; discrepancy tolerance and loss/damage/credit note; actual expense payer/allocation and FX source; time/period semantics for late landed cost; opening/go-live date and evidence; supplier payment/partner participation; contract historical effective intervals; treatment of customer receipts/check bounce/overpayment; Partner claim lifecycle, FX risk, sent-versus-confirmed remittance and max maturity. See Master DB-06 and §12. Fields/technical timestamps must not silently decide these policies.

## Rollout and rollback requirements

1. Build and migrate only in disposable SQL clone restored from a verified backup; migrations additive and preserve old document IDs, attachments, allocations and row versions where meaningful.
2. Deploy schema before compatible code if needed; use explicit legacy/new capability gate and telemetry to prevent mixed posting semantics.
3. For old data with no actual receipt source, mark date provenance unknown/proxy. Do not fabricate effective dates from posting timestamps.
4. Import with manifest and stable source keys, dry-run reconciliation, duplicate detection, resumable chunks and audit. Never mutate `SaleCostAllocation` or stock layer quantities to make totals appear correct.
5. Rollback means disable new entry, restore from verified backup or apply approved compensating events. No destructive down migration after data capture; no silent deletion/rebase of documents.

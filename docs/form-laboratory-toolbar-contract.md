# قرارداد مشترک هدر فرم‌های آزمایشگاه

نسخهٔ قرارداد: ۲ — مرجع اجرایی: `laboratoryToolbarContract` در `toolbarLayoutContract.ts`.

همهٔ فرم‌های ساخته‌شده با `FormSchemaPresentation` از `BaseFormGridBoundary` و همین موتور مشترک استفاده می‌کنند. رفتار در فرم‌ها کپی نمی‌شود. قرارداد در بخش رفتارهای آزمایشگاه نمایش داده می‌شود و `behaviorManifest.toolbarContract` همراه خروجی نهایی هر فرم ثبت می‌شود.

## قوانین قابل اجرا

- جای پیش‌فرض تنظیم ستون‌ها و بزرگنمایی در چپ و جست‌وجو در راست است؛ فضای میانی انعطاف‌پذیر می‌ماند و با عریض‌شدن هدر رشد می‌کند. در عرض کم، جست‌وجو به ردیف بعد می‌رود و سمت راست می‌ماند.
- کادر جست‌وجو، دکمهٔ کناری و هر یک از سه گزینه جداگانه انتخاب می‌شوند. Ctrl یا Command چند جزء را به انتخاب اضافه می‌کند؛ کشیدن هر جزء انتخاب‌شده همهٔ اجزای انتخاب‌شده را با هم جابه‌جا می‌کند. قاب چندانتخابی محدودهٔ واقعی اجزای انتخاب‌شده را نمایش می‌دهد. انتخاب خودکار یا یک‌مرحله‌ای کل گروه جست‌وجو وجود ندارد.
- تغییر ارتفاع هدر نمی‌تواند محتوای آن را پنهان کند یا روی سرستون‌های جدول بیندازد. کمترین ارتفاع از محتوای واقعی محاسبه می‌شود. جابه‌جایی‌های اجزا داخل مرز هدر محدود می‌شوند.
- پیش‌نمایش کشیدن لبه همان هندسه‌ای را نشان می‌دهد که پس از رهاکردن ذخیره می‌شود. لبهٔ مقابل ثابت می‌ماند؛ حداقل ارتفاع قبلی نباید حرکت زنده را مسدود کند.
- چیدمان جدول، محدودهٔ واقعی هدر را پس از جابه‌جایی یا تغییر اندازه از لبهٔ بالا نیز در نظر می‌گیرد؛ جدول از زیر قاب هدر شروع می‌شود. قواعد هدر به کلاس صفحهٔ آزمایشگاه وابسته نیستند و همراه رندر مشترک استفاده می‌شوند.
- تغییر اندازه به قلم، رنگ یا تنظیمات محتوایی دست نمی‌زند.
- هندسه در `schema.tables[].settings.toolbar` سند همان فرم قرار دارد. بازکردن یا جابه‌جایی یک فرم مستقل، قالب مادر و فرم‌های دیگر را بازنویسی نمی‌کند. نمایش داده‌های قدیمی خارج از مرز، در لایهٔ نمایش تصحیح می‌شود؛ سند ذخیره‌شده خودکار تغییر نمی‌کند.

## ارجاع اصلاحات بعدی به آزمایشگاه

برای هر اصلاح قابل استفادهٔ مجدد: ایراد در موتور مشترک اصلاح شود، آزمون مرورگر برای حالت واقعی اضافه شود، این سند و قرارداد رفتار به‌روزرسانی شوند و `npm run validate:form-designer` اجرا شود. هندسهٔ اختصاصی یک فرم فقط با انتخاب صریح مالک به نسخهٔ قالب مادر منتقل می‌شود. تغییر قواعد قرارداد، نسخهٔ جدید می‌خواهد؛ نسخه‌های منتشرشدهٔ قبلی تغییر نمی‌کنند.

## قرارداد سطح ورودی درخت — نسخهٔ ۱

مرجع اجرایی این بخش `futureFormPolicy.compositeDesignerGeometry.treeEditorLayout` است. عنوان، ردیفی مستقل و تمام‌عرض است و فقط ارتفاع آن تغییر می‌کند. سطح ورودی زیر عنوان تا مرز تقسیم با جدول ادامه دارد؛ انتخاب و تغییر رنگ آن شامل فضای خالی زیر ستون‌ها نیز می‌شود. پنج ستون، رنگ و هندسهٔ مستقل دارند. قاب قدیمی کامپوننت هدف انتخاب دیگری ایجاد نمی‌کند.

سطح ورودی و گزارش از حاشیه‌های مشترک `formTheme.css` استفاده می‌کنند. دستگیرهٔ مشترک `BaseFormShell` در مرز واقعی فیلدها متوقف می‌شود و اندازهٔ فیلدها را تغییر نمی‌دهد. اسکرول ردیف‌های گزارش در موتور استاندارد جدول باقی می‌ماند و هدر گزارش با پنل بالا پوشانده نمی‌شود. حفظ عرض ستون‌های سفارشی ممکن است فضای استفاده‌نشده در جدول باقی بگذارد؛ عرض ستون‌ها خودکار کشیده نمی‌شود.

`Ctrl+L` برای ستون‌های انتخاب‌شده اندازه‌ها را هماهنگ می‌کند، میانگین فاصله‌های موجود را نگه می‌دارد و ردیف کامل را وسط محدودهٔ ویرایشگر قرار می‌دهد. کلیدهای جهت جابه‌جایی فیزیکی و هنگام فوکوس روی دستگیره، تغییر اندازه را انجام می‌دهند. تغییرات هندسی قدیمی در لایهٔ نمایش سازگار می‌شوند و بازخوانی فرم نباید داده یا تاریخچه را بازنویسی کند.

آزمون‌های اجرایی: `tests/tree-geometry.browser.mjs` و `tests/tree-report.browser.mjs`. دومی رنگ زندهٔ سطح، ذخیره و بازگشایی در حافظهٔ جدا، دستگیرهٔ تقسیم و نمای عملیاتی را نیز بررسی می‌کند؛ در صورت وجود نسخهٔ پشتیبان، هندسهٔ همان فرم در پروفایل موقت بازخوانی می‌شود.

Shared grid row navigation: left-click selects the current row and clears cell selection; ArrowUp/ArrowDown browse visible filtered/sorted rows while retaining grid focus. Cell selection and its copy/filter menu start with right-click (Ctrl/Shift-right-click retain multi/range selection). Hierarchy report row markers are separate from actual keyboard focus and never transfer focus to the editor.

Footer action context menus expose the existing shared action-text editor for Persian/English/localized labels and displayed shortcut text. Text editing targets the clicked action only, preserves its stable action ID and behavior, and uses the same Designer draft, Undo and persistence as the sidebar editor.

The shared font panel lists every integer size from 8 through 20. Opening it focuses and selects the exact numeric size, including sizes absent from the preset list; selected font/style/size options stay visibly highlighted while another control has focus. Initial field values resolve inherited Designer defaults, action text inherits its button formatting, and grid fonts inherit the table font before per-column overrides.

Font-dialog inputs and lists keep white backgrounds during focus; current options use a persistent light-gray selection. Each list reveals its selection only when its own value changes, so changing the font family never scrolls the size or style selection out of view.

The current non-preset font size is inserted in numeric order only for that current value and removed when another size is selected. Font-panel styles must also apply to dialogs portaled outside the application root.

Font-dialog control scopes override the global editable-focus fill to white. Native list options retain black text, including the active selected option, with a light-gray selection background; these UI colors do not alter the chosen font color or its sample preview.

Text-only component surfaces (buttons, captions, status and breadcrumb content) consume the shared input textAlign and verticalTextAlign settings. Horizontal alignment applies to the full content width, including breadcrumb flex content; vertical alignment applies within the saved field height. These commands must not move or resize the field rectangle or reflow adjacent components.

Starting a geometry gesture freezes measured flow-input boxes before preserving flex slots. Pointer-down alone never refits nested content; only an actual size change fits the changed field's content to its new box. Unselected toolbar text must not wrap or change height during another field's selection, move or resize preview.

Registered geometry preview is created only after real pointer movement, never on a stationary press. Capture content sizes before any ancestor/slot writes; preserve the root's computed CSS dimensions rather than its transformed border-box dimensions, and keep unselected content from flex-shrinking until the preview is restored.

Selected-row color overrides alternate-row and cell backgrounds uniformly. Keyboard navigation scrolls only the table viewport by the minimum distance required to reveal the next row; it never scrolls an ancestor form. Report-linked hierarchy columns preserve sibling order and align their current-path markers on a common third-row slot below search, reserving blank preceding slots where needed and leaving unused depths empty. Internal list scrolling exposes surrounding siblings without moving focus from the grid.

پس از Ctrl+L، فیلدها برای ویرایش دستی قفل نمی‌شوند. حرکت، کشیدن لبه‌ها، کلیدهای جهت‌دار و تغییر اندازهٔ عددی باید از عرض قابل‌استفادهٔ فعلی پنل با حاشیهٔ نیم‌سانتی‌متری در دو طرف استفاده کنند، حتی اگر عرض ذخیره‌شدهٔ چیدمان کوچک‌تر باشد. این مرز موقت است؛ عرض ذخیره‌شده، مبدأ مختصات و جای فیلدهای انتخاب‌نشده نباید برای بازکردن فضا تغییر کند. قواعد همسایه و جلوگیری از برخورد، در صورت فعال‌بودن، برقرار می‌مانند. این قرارداد در laboratoryResizeContract و JSON تحویل فرم صادر می‌شود.

تغییر اندازهٔ جبرانی همسایه فقط با انتخاب صریح افقی/عمودی در طراحی فعال می‌شود؛ سیاست عمومی رفتار فرم آن را خودکار فعال نمی‌کند. این دو کنترل کنار مشخصات انتخاب جاری در دسترس‌اند و بازگشت به پیش‌فرض آن‌ها را خاموش می‌کند. اگر در ضلع موردنظر همسایهٔ مناسب وجود نداشته باشد، تغییر اندازهٔ تک‌فیلد مستقل و در حدود حاشیهٔ پنل ادامه می‌یابد؛ حداقل اندازه و محدودیت برخورد برای همسایهٔ واقعی همچنان محفوظ است. Ctrl+L این حالت را فعال نمی‌کند.

Ctrl+L برای انتخاب بخشی از فیلدهای بوم نیز فعال است: فقط همان انتخاب‌ها با میانگین حسابی عرض، ارتفاع و فاصلهٔ لبه‌های ورودی یکسان و در یک ردیف تراز می‌شوند. ترتیب فیزیکی و فیلدهای انتخاب‌نشده محفوظ‌اند. فرمان یکسان‌سازی در راست‌کلیک نیز همین مسیر مشترک را اجرا می‌کند؛ وسط‌چین مستقل از تغییر اندازه است.

نگهداری محلی پشتیبان فرم: در هر ذخیرهٔ بازیابی، برای هر فرم فقط سه نسخهٔ آخر نگهداری می‌شود؛ سند جاری، Undo/Redo جاری، فرم ذخیره‌شده و بستهٔ تأییدشدهٔ اتصال پاک نمی‌شوند. پاک‌سازی نسخه‌های قدیمی و نوشتن سند جدید در یک نوشتن اتمیک انجام می‌شود؛ شکست ذخیره، دادهٔ قبلی را حفظ و اتصال به منو را همچنان مسدود می‌کند.

### Shared entry and rule editor reference (2026-11-10)
- Form-wide settings own Enter order (number or up/down), composite uniqueness and cross-field dependencies. Per-field settings own required, independent uniqueness, normalization, read-only and value behavior. These edit the existing schema; rules are not copied onto unrelated fields.
- FieldFocusOrderControls and FormRelationshipControls are reachable from FormDocumentSettings and the structure context menu. NumberControl/FormValueList must use orderedEntryControls, including saved focusOrder, instead of a private contact-field sequence.
- Runtime entry focus uses pale yellow and a neutral focus ring; green selection handles belong to Designer only. Persons retains its existing shortcut settings through the shared FormSettingsButton in its header. This does not migrate the legacy Persons renderer to the schema renderer.
- ManagedDesignList archived/deleted views offer an explicit return to active designs and clear the search when returning. No recovery or operational records are deleted by that action.
- Focused regression: frontend/tests/focus-navigation.browser.mjs. No production storage is used by this fixture.

- Enter sequence is a subsection of the single form-wide rules editor (قواعد گروهی و ارتباط فیلدهای فرم), not a separate context-menu item. The same grouping is used in FormDocumentSettings.

- Enter-order rows use a shared fixed-column layout and per-field enterEnabled checkbox. Missing enterEnabled means enabled; read-only/derived fields are excluded. Unchecking skips the field in Enter and horizontal sequence navigation; pointer selection remains available. Default order follows rendered form layout; explicit saved positions remain intact. Restore-layout clears ranks only, preserving participation choices. The optional boolean is serialized in the existing field schema.

- Shared directional navigation: Left/Right follow the saved Enter sequence across row boundaries, including native selects and selected text. After an intentional click inside text, caret editing stays native until its boundary. Up/Down stay within the current component (native selects or FormValueList closed-choice browsing), never jump between form rows. Enter confirms the current value and follows saved Enter participation/order.

- Fixed editor height and scrollable content extent are independent. In automatic overflow mode the view excludes unused Canvas tail, even for fixed panels; saved Canvas dimensions and field coordinates stay untouched. Real field overflow remains scrollable; explicit scroll mode remains respected. Regression: headerDesignerRegression.test.mjs and scrollExtent browser fixture.

- Horizontal navigation refinement: Left/Right follow the saved Enter sequence and participation across row boundaries, rather than physical-neighbor lookup. In RTL Left advances and Right reverses; LTR is reversed. The first/last boundary retains focus. Mouse selection stays available for unchecked fields.

- انتخاب کامپوننت در ویرایش ساختار باید نوع فعلی فیلد را نشان دهد؛ انتخاب جدید در پیش‌نویس همان پنجره اعمال می‌شود و دکمهٔ تبدیل جداگانه ندارد. ثبت نهایی و انصراف از مسیر موجود انجام می‌شوند؛ شناسه، چیدمان، قواعد و اتصال‌ها حفظ می‌شوند.

- اسکرول عمودی پنل فیلدها فقط با سرریز واقعی محتوا فعال می‌شود؛ تنظیم قدیمی scroll در نمایش به auto تبدیل می‌شود و فضای خالی Canvas یا جابه‌جایی فیلدها دوباره به انتهای پنل افزوده نمی‌شود. مختصات ذخیره‌شده تغییر نمی‌کند.

- یک فیلد در هر جدول تنها به یک ستون متصل می‌شود؛ ایجاد ستون، انتخاب مبدأ و اتصال دستی همگی این قاعده را کنترل می‌کنند. حذف ستون تکراری ارتباط معتبر باقی‌مانده را قطع نمی‌کند و هشدار واقعیِ فیلد بدون ستون حفظ می‌شود.

- نمایش کلیدهای پایین از formActionVisible پیروی می‌کند: مشاهده بدون ذخیره؛ ایجاد و ویرایش فقط ذخیره و انصراف/خروج. در خود طراحی همهٔ کلیدها برای تنظیم ظاهر نمایش داده می‌شوند؛ نمای عملیاتی و ورود آزمایشی از قانون حالت فرم پیروی می‌کنند؛ تعریف کلیدها و تنظیمات ظاهری حذف نمی‌شود.
# بازیابی خطای بازشدن فرم

خطای یک صفحه نباید کاربر را در بن‌بست نگه دارد: تلاش دوباره، بستن صفحه و رفتن به داشبورد باید در همان صفحهٔ خطا در دسترس باشند. تلاش دوباره فقط صفحهٔ خطادار را بازسازی می‌کند؛ طراحی‌ها، پشتیبان‌ها و تغییرات زبانه‌های دیگر پاک نمی‌شوند. تازه‌سازی کامل برنامه نیازمند هشدار دربارهٔ تغییرات ذخیره‌نشده است. پنل طراحی باید سند بدون فیلد یا بدون انتخاب را با مقادیر پیش‌فرض و کنترل‌های غیرفعال نمایش دهد و نباید شناسهٔ ناموجود را بخواند.

## Warehouse definition contract (2026-11-10)

Warehouse definition reuses the brand-sized OperationalFormFrame and standard server grid; address uses FormValueList and optional custodian uses the Persons SystemLookup. Warehouse creation includes one protected ground-floor receiving dock; additional floors may each have one explicitly created dock. Full zone codes are normalized and unique per warehouse; names are normalized and unique within each floor, including simultaneous submissions. Contract version 40 below supersedes the former single-floor rule. Custodian changes retain non-overlapping periods, actor and reason; old records remain protected. Inventory operations are a separate phase: receipts (including inter-warehouse receipts) enter only the destination receiving dock; origin may be any zone; internal zone transfers retain movement history. This definition release does not claim implementation of inventory transfers. Personal customization never changes the Laboratory master.
# قرارداد تعریف انبار، طبقه و زون — نسخه ۴۰

- پنل انبار سه ردیف دارد: کد و نام با عرض مساوی؛ تعداد طبقات، موقعیت انبار و انباردار اختیاری از اشخاص با سه عرض مساوی؛ آدرس مشترک و توضیحات با همان دو عرض ردیف اول.
- تعداد طبقات پیش‌فرض یک و حداکثر پنج است. همکف ۱، طبقه اول ۲ و طبقات بعدی به ترتیب شماره می‌گیرند. حذف طبقه دارای زون یا سابقه ممنوع است.
- زون‌ها فرم مستقل از اجزای مشترک دارند: فیلدها بالا، جدول استاندارد با جست‌وجو، فیلتر و مرتب‌سازی سمت سرور پایین؛ نوار کلیدهای مشترک، Space/Insert/F3/Escape و قواعد نمایش ذخیره/انصراف.
- کد کامل زون «شماره طبقه-پسوند دلخواه» است؛ پیشوند اجباری، پیشنهاد کد سمت سرور و کنترل یکتایی کد کامل در انبار و نام نرمال‌شده در طبقه انجام می‌شود.
- بارانداز همکف خودکار است. برای طبقات دیگر گزینه ایجاد بارانداز وجود دارد؛ هر طبقه حداکثر یک بارانداز با نام ثابت «بارانداز» دارد. تغییر نام، نقش، طبقه، حذف یا غیرفعال‌سازی آن ممنوع است.
- کپی زون‌ها فقط بین طبقات همین انبار، با پیش‌نمایش و انتخاب موارد غایب مقصد انجام می‌شود. بارانداز، موجودی و سوابق کپی نمی‌شوند. پیشوند به مقصد تغییر می‌کند و کنترل تکرار در تراکنش سرور دوباره اجرا می‌شود. انصراف هیچ داده‌ای ثبت نمی‌کند.
- این قرارداد در مرجع رفتار آزمایشگاه و JSON انبار و زون ذخیره می‌شود. اجرای جابه‌جایی موجودی بین زون‌ها/انبارها همچنان مرحله مستقل است.


## موقعیت انبار و کنترل طبقات — قرارداد ۴۰

- موقعیت انبار اجباری است: داخل محوطه شرکت یا خارج محوطه شرکت. انتخاب پیش‌فرض ندارد؛ موقعیت انبارهای قبلی نامشخص می‌ماند تا مدیر آن را تعیین کند.
- تعداد طبقات عدد صحیح ۱ تا ۵ است؛ پیام اعتبارسنجی فرم و سرور فارسی است. ارتقا در صورت وجود طبقات بیشتر بدون حذف داده متوقف می‌شود.
- قرارداد مرحله بعدِ انتقال: انتقال کاملاً داخلی به تأیید نگهبانی نیاز ندارد؛ عبور از مرز محوطه نیازمند تأیید مدیر و خروج نگهبانی و تأیید مستقل دریافت مقصد است. فاصله خروج تا دریافت وضعیت «در راه» دارد؛ موجودی قابل استفاده مقصد پس از دریافت ایجاد می‌شود. این تغییر فرم، اجرای گردش انتقال موجودی را شامل نمی‌شود.

## قرارداد ۴۱ — نمایش جدول هنگام ورود اطلاعات
در حالت ایجاد و ویرایش، رکوردهای جدول و دریافت صفحه‌ای آن حفظ می‌شوند. جست‌وجو، مرتب‌سازی و فیلتر فعال می‌مانند. انتخاب ردیف نباید پیش‌نویس ذخیره‌نشده را جایگزین کند. محدودیت طراحی از ورود اطلاعات جداست.

## قرارداد ۴۲ — انتخاب خالی و نمایش انتخاب‌گر
انتخاب‌گر اختیاری باید گزینهٔ خالی قابل انتخاب داشته باشد؛ ذخیرهٔ خالی، رابطه را null می‌کند و تاریخچه محفوظ می‌ماند. نمایش فیلد بسته می‌تواند فقط نام باشد؛ فهرست نتایج و جست‌وجو همچنان کد و نام را دارند. انباردار از همین قاعده پیروی می‌کند.

## قرارداد ۴۳ — ردیف خالی ثابت
ردیف خالی انتخاب‌گر اختیاری، با ارتفاع مشخص زیر جست‌وجو و بیرون از نتایج اسکرول‌شونده باقی می‌ماند. بدون عبارت جست‌وجو انتخاب اولیه خالی است؛ با تایپ، نتیجهٔ مرتبط فعال می‌شود. کلیدهای بالا/پایین و Enter انتخاب را انجام می‌دهند.

## قرارداد ۴۴ — وراثت فرم‌های محاوره‌ای
فرم مستقل یا محاوره‌ای باید ناحیهٔ ورود را با person-form-grid یا data-entry-grid معرفی کند و ترتیب فیلدها را مشخص کند؛ Enter و چپ/راست همان موتور مشترک formInteraction را اجرا می‌کنند. فیلتر و مرتب‌سازی جدول داخل نزدیک‌ترین لایهٔ FormDocumentDialog باز می‌شود تا پشت فرم یا زیر اسکرول قرار نگیرد.

## قرارداد ۴۵ — نام نمایشی زون با طبقه
شمارهٔ طبقه، مستقل از نام ذخیره می‌شود و هنگام نمایش نام زون به صورت «۲ — قفسه الف» افزوده می‌شود. نام خام، کد زون و نام انبار تغییر نمی‌کنند. در انتخاب‌گرهای انتقال آینده، مسیر انبار ← طبقه ← زون و محدودیت زون به طبقهٔ منتخب الزامی است؛ عملیات انتقال در این تغییر پیاده‌سازی نمی‌شود.

## قرارداد ۴۶ — زبان تایپ داخل فیلد
فیلدهای متنی قابل ویرایش، دکمهٔ کوچک تغییر زبان در لبهٔ چپ داخل فیلد دارند؛ «EN» مقصد انگلیسی و «فا» مقصد فارسی است. Alt تنها، پس از رهاشدن، همان کار را می‌کند؛ کلیدهای ترکیبی، ورود ترکیبی IME، چسباندن متن، Enter، جهت‌ها و F3 حفظ می‌شوند. تا اولین تغییر، تایپ عادی سیستم برقرار است. تغییر زبان فقط بر نویسه‌های بعدی همان فیلد اثر دارد؛ متن قبلی، مکان نشانگر و انتخاب متن عوض نمی‌شوند. زبان صفحه‌کلید ویندوز تغییر نمی‌کند. کدها، عددها، فیلدهای فقط‌خواندنی و غیرفعال مستثنا هستند. تنظیم اختیاری `field.typingLanguage` با `enabled` و `initial: auto/fa/en` در JSON قابل ذخیره است. اجرا تنها در مسیر مشترک `installFormInteraction` است و فرم‌های عملیاتی و پیش‌نمایش آزمایشگاه از آن استفاده می‌کنند.

## قرارداد ۴۷ — کنترل خطا در همان فیلد
`useFieldValidation` مسیر مشترک کنترل مقدار هنگام تایپ، Enter، Tab، حرکت افقی، خروج با موس و ذخیره است. پیام فارسی کنار همان فیلد و نشانهٔ نامعتبر نمایش داده می‌شود؛ تا اصلاح مقدار، ادامهٔ ورود مجاز نیست. Escape و انصراف مسدود نمی‌شوند. پاسخ دیررس پس از تغییر متن، والد، رکورد یا انصراف نباید فوکوس و خطا را تغییر دهد. خطای شبکه به معنی معتبر بودن مقدار نیست؛ متن حفظ می‌شود و امکان تلاش مجدد وجود دارد.

یکتایی از `FieldValidationController` و دیتابیس بررسی می‌شود، مستقل از صفحه و فیلتر جدول. کنترل نوشتن، تراکنش و محدودیت‌های دیتابیس همچنان مرجع نهایی ثبت هم‌زمان‌اند. ویرایش همان شناسه تکراری نیست. قانون جدیدی برای ممنوع‌کردن نام‌های مجاز ساخته نمی‌شود.

|---|---|
| انبار | کد یکتا، نام اجباری، طبقات ۱ تا ۵، موقعیت اجباری، طول متن |

| برند | کد یکتا با قواعد فعلی حروف و عدد، نام اجباری؛ نام برند الزام یکتایی سراسری ندارد |

## قرارداد ۴۸ — انتخاب کد پیشنهادی
کد پیشنهادی هنگام ورود به فیلد کامل انتخاب می‌شود؛ اگر پیشنهاد پس از فوکوس از سرور برسد، همان کد نیز کامل انتخاب می‌شود. بعد از آغاز تایپ، جابه‌جایی به فیلد دیگر یا انصراف، پاسخ دیررس نباید متن، انتخاب یا فوکوس کاربر را تغییر دهد. قاعده در مسیر مشترک installFormInteraction اجرا می‌شود. رفتار Escape در این اصلاح تغییر نمی‌کند.

## قرارداد ۴۹ — Alt کوتاه و مستقل
تغییر زبان فقط پس از رهاکردن Alt مستقل با مدت حداکثر نیم‌ثانیه انجام می‌شود. نگه‌داشتن طولانی‌تر، تکرار کلید، ترکیب با هر کلید دیگر، تغییر فوکوس یا کلیک، تغییر زبان را لغو می‌کند.

## قرارداد ۵۰ — کدها مستثنا از تغییر زبان
کادرهای کد دکمهٔ فارسی/انگلیسی ندارند و Alt زبان آن‌ها را تغییر نمی‌دهد. کامپوننت کد با data-code-input=true شناخته می‌شود، حتی اگر نام فیلد سفارشی باشد. حروف تایپی فقط لاتین و اعداد ذخیره‌شده انگلیسی‌اند؛ ارقام فارسی و عربی به انگلیسی تبدیل می‌شوند. چسباندن یا ورود ترکیبی متن غیرمجاز پذیرفته نمی‌شود. قالب، طول و یکتایی هر کد همچنان مطابق قواعد همان کد کنترل می‌شود.

## قرارداد ۵۱ — پوشش تایپ داخل کامپوننت و جست‌وجو
تمام کادرهای متنی قابل ویرایش، شامل ورود و اصلاح آدرس، پنجره‌های متنی کامپوننت، جست‌وجوی جدول و فیلتر، از کنترل مشترک فارسی/انگلیسی استفاده می‌کنند. پنجرهٔ منتقل‌شده به لایهٔ دیگر همچنان به کامپوننت مبدأ خود متصل است و دکمهٔ زبان بالای همان پنجره قابل کلیک می‌ماند؛ فرم زمینه در زمان پنجرهٔ مسدودکننده فعال نمی‌شود. هندسهٔ ذخیره‌شده عوض نمی‌شود. کدها، تلفن‌ها، عددها و فیلدهای فقط‌خواندنی یا غیرفعال مستثنا هستند. Alt کوتاه مستقل مطابق قرارداد ۴۹ است.

## قرارداد ۵۲ — انحصار پنجرهٔ باز کامپوننت
تا بسته‌شدن کامپوننت با ثبت، انصراف یا Escape، کلیک، فوکوس، Tab و میان‌برها محدود به همان پنجره‌اند. پوشش شفاف، جدول و فیلدهای زمینه را از تعامل خارج می‌کند؛ دکمه‌های زبان زمینه نیز مخفی می‌شوند. فقط کادرهای متنی لایهٔ فعال دکمهٔ زبان دارند. جست‌وجوی جدول و جست‌وجوی فیلتر نیز هنگام فعال‌بودن لایهٔ خود از کنترل مشترک زبان استفاده می‌کنند. کدها مستثنا و هندسهٔ فرم محفوظ است.

## قرارداد ۵۳ — زبان فقط در لایهٔ رویی
بازشدن فیلتر ستون، فیلتر سفارشی یا پنجرهٔ کامپوننت، دکمه‌های زبانِ فرم و جدول زمینه را مخفی می‌کند. پس از بستن، دکمه‌های مجاز دوباره ظاهر می‌شوند. کنترل مشترک علاوه بر لایهٔ فعال، پوشیده‌بودن واقعی کادر را هم بررسی می‌کند؛ دکمهٔ زبانِ کادر پوشیده نباید روی پنجرهٔ جلویی دیده یا قابل کلیک باشد. این کنترل برای جدول اصلی و جدول داخل پنجره یکسان است.

### قرارداد ۵۴ — F8 و پیام اعتبارسنجی بدون تغییر چیدمان

F8 در ExcelGridFilterScope جدول فعال پیاده می‌شود، نه در صفحه آزمایشگاه. تمام فیلترهای ستون و جست‌وجو و معکوس جست‌وجو پاک می‌شوند؛ ترتیب مرتب‌سازی و ظاهر و سایر جدول‌ها حفظ می‌شوند. پنجره فیلتر و فرم مودال مالک مشخص دارند. آداپتر سرور باید درخواست تازه با filters خالی دریافت کند.
پیام اعتبارسنجی در پنجره کوچک ثابت زیر فیلد قرار می‌گیرد؛ ردیف‌ها تغییر اندازه یا مکان نمی‌دهند. با تایپ پیام بسته می‌شود؛ اعتبارسنجی هنگام خروج/ثبت برقرار است. متن خطا هرگز مقدار فیلد نیست.
آزمون مرورگری مشترک: frontend/tests/grid-reset-validation.browser.mjs؛ پوشش جدول محلی، سروری، فیلتر پورتال، جداسازی مودال، حفظ فوکوس و عدم جابه‌جایی ردیف.

### قرارداد ۵۵ — ورود و ثبت گروهی زون

ورود چندتایی با دکمه و کلید +، حذف ردیف پیش از ثبت و F3 برای ثبت یکپارچه است. حداکثر هر درخواست ۱۰۰ ردیف دارد. کدهای همه ردیف‌ها پیش از ثبت از سرور پیشنهاد می‌شوند؛ پیشوند طبقه ثابت و کدهای اشغال‌شده کنار گذاشته می‌شوند. پیشنهاد رزرو نیست و ثبت در تراکنش قفل‌شده دوباره یکتایی تمام نام‌ها و کدها را بررسی می‌کند. خطای هر ردیف مانع کل ثبت می‌شود؛ متن‌ها و فوکوس حفظ می‌شوند. Escape فقط پیش‌نویس‌ها را کنار می‌گذارد و پاسخ پیشنهاد لغوشده نباید برگردد. جدول موجود هنگام ورود حفظ می‌شود. بارانداز، موجودی و ویرایش تکی از این ثبت مستقل‌اند. آزمون مرورگری zone-batch و آزمون SQL WarehouseZoneBatchTests مرجع این آداپتر هستند؛ فرم آینده باید آداپتر تراکنشی و شواهد آزمون خودش را داشته باشد.

### Zone entry follows the Product Group name queue
The plus button stays beside the single active name input. Mouse plus and keyboard + queue its name, clear it, and keep focus there; no extra blank input is created. Queued names can be removed. F3 saves the queue plus any nonempty current name atomically, with visible server-proposed codes. Empty current input does not block saving queued names.

### 57 — Anchored zone queue and operational font dialog
The name-entry plus is inside the focused nonempty input beside the language toggle and hidden in view mode. Queued names/codes/removal actions use a viewport-bounded floating list anchored below the input, extending left as needed. It never occupies grid/editor layout space. Operational typography uses the shared draggable document dialog, effective rendered font state, and independent none/single/double decoration. The green Apply colors are invariant during hover, focus and press.

### 58 — پیش‌نمایش قلم و نشست ویرایش زون

تغییر قلم پیش از تأیید روی هدف واقعی نمایش داده می‌شود؛ لغو یا بستن پنجره، وضعیت قبلی را برمی‌گرداند. تأیید سبز در همه حالت‌ها ثابت است. طبق درخواست مالک برای بررسی ظاهری، مسیر سبز دیگر خودکار بولد نمی‌شود؛ رنگ سبز و خاکستری کم‌رنگ گزینه‌های اطراف محفوظ است. تنظیم صریح قلم کاربر همچنان معتبر است.

زون تک‌طبقه کنار نام شماره طبقه ندارد؛ در چندطبقه شماره در سمت راست و بدون خط تیره است. برچسب جدول و فیلتر شامل نام طبقه است. ویرایش زون هر انبار با قفل اختصاصی نشست SQL فقط به یک کاربر و یک تب مرورگر داده می‌شود؛ تمدید هر ۳۰ ثانیه، انقضا پس از ۱۲۰ ثانیه و آزادسازی هنگام خروج. از دست رفتن نشست، پیش‌نویس را حذف نمی‌کند و ثبت تا بازیابی نشست متوقف است. پیشنهاد کدها هنگام تازه‌سازی پاک نمی‌شود و صف شناور، هندسه یا داده‌های جدول اصلی را تغییر نمی‌دهد.

### 59 — هدایت مستقیم به خطای تأیید طراحی

هنگام توقف تأیید به دلیل منابع قوانین یا ساختار جدول، پیام قابل اقدام نمایش داده می‌شود؛ پنجره مجوزها کنار می‌رود و تنظیمات همان فیلد، گروه یکتایی، وابستگی یا جدول باز می‌شود. گروه ناقص قرمز و کنترل مربوط قابل دسترس با فوکوس است. هیچ قانونی خودکار حذف یا تأیید نمی‌شود. اعتبارسنجی ساختار طراحی از اعتبارسنجی رکورد خالی عملیاتی جداست.

### 60 — وضعیت روشن اتصال فیلد و ستون

بخش مشاهده ستون‌های متصل، نام واقعی فیلد و جدول/ستون را در دو نشان سبز کنار هم نمایش می‌دهد و فهرست اتصال روی ستون فعلی قرار می‌گیرد. نبود اتصال با عبارت صریح «بدون ستون» دیده می‌شود. هشدار حذف ستون یا اختلاف عنوان محفوظ است؛ سبز بودن نشان اتصال، تأیید خودکار اختلاف عنوان نیست. قطع، اتصال مجدد و تثبیت مستقل همچنان از عملیات مشترک ساختار استفاده می‌کنند.

### 61 — تغییر زبان در ورود اطلاعات آزمایشی

در حالت ورود داده موقت، مالکیت کلیک و دستگیره‌های Designer غیرفعال است؛ کلید فارسی/انگلیسی و Alt کوتاه مشترک روی ورودی‌های متنی قابل ویرایش، سرچ و ورودی پنجره‌های کامپوننت فعال می‌ماند. کد، عدد و فقط‌خواندنی مستثنا هستند. بازگشت به طراحی، ابزارهای طراحی را بدون تغییر هندسه یا داده ذخیره‌شده برمی‌گرداند.

### 62 — متن ترکیبی پیوسته

اجزای فیلد نمایشی محاسبه‌شده در یک ظرف متن پیوسته قرار می‌گیرند. تراز افقی و عمودی روی کل متن اعمال می‌شود؛ تراز عمودی نباید هر منبع را به سطر جدا ببرد. فاصله جداکننده پیش‌فرض است، چندخطی صریح با جداکننده سطر جدید محفوظ است و شکست طبیعی متن تنها با کمبود واقعی عرض رخ می‌دهد. آزمون واقعی runtime-typing-focused.browser.mjs، تایپ زبان و متن ترکیبی وسط‌چین را پوشش می‌دهد.

### 63 — اتصال منبع عملیاتی بدون محدودیت طراحی

فهرست منبع فقط از آداپترهای ثبت‌شده فرم‌های عملیاتی ساخته می‌شود؛ نسخه‌های آزمایشگاهی منبع داده نیستند. شناسه منبع در تنظیم فیلد و JSON محفوظ است. منبع گروه کالا تمام گروه‌های ذخیره‌شده در همه سطح‌ها و شاخه‌های ناتمام را با شناسه پایدار، کد عمومی ریشه و مسیر کامل ارائه می‌کند. انتخاب منبع در طراحی محدودیت عمق یا برگ بودن اعمال نمی‌کند؛ قواعد تخصیص در ثبت عملیاتی مصرف‌کننده کنترل می‌شوند. جست‌وجوی صفحه‌بندی‌شده سمت سرور و مجوز مشاهده الزامی است. رفتار جست‌وجو و انتخاب از SystemLookup مشترک می‌آید؛ ایجاد رکورد تنها با آداپتر ایجاد مجاز همان منبع فعال است.

تیک‌های تنظیمات کامپوننت باید با متن همان گزینه در یک ردیف، با اندازه ثابت ۱۷ پیکسل و فاصله نزدیک نمایش داده شوند؛ چیدمان عمودی ورودی‌های معمولی نباید روی این گزینه‌ها اعمال شود. آزمون lookup-sources.browser.mjs مرکز عمودی، فاصله و اندازه واقعی تیک‌ها را کنترل می‌کند.

### 64 — رنگ‌ها و مقادیر با ثبت گروهی

کامپوننت base-form.batch-values در کتابخانه و تبدیل فیلد قابل انتخاب است. از ویرایشگر مشترک فهرست استفاده می‌کند؛ شناسه فنی مخفی و پایدار از متن کد یا نام رنگ جداست. + و کلید + ردیف موقت اضافه می‌کنند، F3 مجموعه را پس از اعتبارسنجی یکجا تحویل می‌دهد و Escape تغییرات موقت را لغو می‌کند. خطای تحویل، ورودی‌ها را حفظ می‌کند. سه نمونه سازگار مانند 110، 120، 130 مقدار 140 را انتخاب‌شده پیشنهاد می‌دهند؛ الگوی نامشخص پیشنهاد ندارد. مقایسه تکرار با یکسان‌سازی حروف، ارقام و فاصله‌ها فقط در همان مجموعه انجام می‌شود. آزمایش داده موقت است؛ اتصال عملیاتی باید شناسه قطعی سرور و ثبت مجموعه زیر والد مربوط را فراهم کند.

هندسه انتخاب از تعاریف سیستم: در چیدمان ثابت و جاری، ارتفاع باید در تمام قاب‌های SystemLookup تا سطح کادر قابل‌دیدن منتقل شود؛ عدد قاب طراح و کادر واقعی فیلد باید با تلرانس ۰٫۱ پیکسل برابر باشند. Ctrl+L نباید فقط قاب نامرئی را یکسان کند. آزمون lookup-geometry.browser.mjs کادر واقعی انتخاب گروه، فهرست و ورودی عادی را در ارتفاع‌های کسری مقایسه می‌کند. اصلاح نمایشی نباید ابعاد ذخیره‌شده را بازنویسی کند.

### 65 — اعشار و متن همراه منابع نام کامل

ورودی عددی پیش‌فرض اعشارپذیر است. تعداد اعشار در قوانین همان فیلد از صفر (صحیح) تا ۱۲ یا آزاد قابل انتخاب و در numericSettings ذخیره می‌شود؛ مقدار کاربر گرد نمی‌شود و خطای دقت فارسی است. کدهای فنی از این قانون اعشار مستثنا هستند. در ساخت نام کامل برای هر منبع، فقط مقدار، مقدار و برچسب، برچسب و مقدار یا فقط برچسب قابل انتخاب است؛ متن همراه می‌تواند برچسب کامل زبان جاری یا متن دلخواهی مثل «لا» و «دنیر» باشد. منابع خالی همراه برچسب حذف می‌شوند؛ پیش‌نمایش و ثبت از یک حل‌کننده استفاده می‌کنند. sourceFormats و دقت اعشار در JSON و تحویل عملیاتی حفظ می‌شوند؛ سرور مصرف‌کننده نیز باید قرارداد را کنترل کند. تنظیمات قدیمی بدون تغییر متن، مقدار تنها را نشان می‌دهند.

### 66 — یک کالای اصلی و چند رنگ

رنگ‌های ثبت گروهی جزئیات همان رکورد اصلی‌اند: details[fieldId] شامل شناسه فنی پایدار و متن رنگ است؛ کد عمومی کالا فقط یک بار تخصیص می‌یابد. ### 67 — هویت واقعی کامپوننت در تنظیمات ساختار

منوی کتابخانه باید نوع واقعی کنترل را از شناسه، تعریف کتابخانه، پیش‌تنظیم و نوع/تنظیمات مؤثر سند بخواند؛ فهرست‌های قدیمی با شناسهٔ قاب عمومی نباید «فیلد عادی» نمایش داده شوند. نام برچسب ملاک تشخیص تلفن یا موبایل نیست. تبدیل، بازکردن مجدد و JSON باید همین هویت را حفظ کنند؛ اصلاح نمایش مجوز تغییر خودکار نوع، داده یا چینش فرم نیست. آزمون مرورگری component-identity این قرارداد را کنترل می‌کند.

### 68 — مقدار واقعی و گزارش دادهٔ آزمایشی

### 69 — انتخاب بخشی از برچسب برای نام کامل

### 71 — بسته‌بندی، آداپتور همان کامپوننت عنوان

API عملیاتی این مسیر در مرحله اتصال پیاده خواهد شد.


### ۷۲ — زبان تایپ در فیلدهای متنی ورود آزمایشی

### ۷۳ — ورودی دوتایی بسته‌بندی و اندازهٔ فهرست مشترک

فهرست مشترک FormValueList دو دستگیرهٔ پایین چپ و راست برای تغییر اندازه با موس دارد. اندازه در همین مرورگر به تفکیک فرم، فیلد و کامپوننت حفظ و در نمایش بعدی با محدودهٔ صفحه تطبیق داده می‌شود؛ اندازهٔ فیلد مادر و چینش فرم تغییر نمی‌کند. ورودی دوتایی بسته‌بندی حداقل عرض مناسب دارد تا نام و CBM هر تن همزمان با کلیک و صفحه‌کلید قابل استفاده باشند. نام‌ها از مرجع مشترک پیشنهاد می‌شوند و تطبیق نام نرمال‌شده همان شناسه را استفاده می‌کند؛ ضریب CBM هر کالا جداست. مرجع آزمایشگاهی در حافظهٔ مرورگر است؛ اشتراک عملیاتی بین کاربران نیازمند منبع سرور و آداپتر ثبت مجاز است.


### ۷۴ — تداوم نشست و حفاظت از فرم باز

خروج خودکار زمان‌دار سمت مرورگر حذف شده است؛ sessionTimeoutMinutes فقط برای سازگاری قرارداد ذخیرهٔ قبلی حفظ می‌شود و کنترل خروج نیست. تمدید نشست فقط از مسیر معتبر سرور انجام می‌شود؛ پاسخ 401 با یک تمدید مشترک و حداکثر یک تلاش مجدد پاسخ داده می‌شود. خطای شبکه در ثبت دوباره ارسال نمی‌شود. اگر تمدید مجاز نباشد، محیط کار و مقادیر ذخیره‌نشده در حافظه زنده می‌مانند، غیرفعال می‌شوند و ورود مجدد همان حساب لازم است؛ مجوزها پس از ورود دوباره از سرور خوانده می‌شوند. خروج دستی و بستن تب یا فرم با Escape تأیید می‌خواهد؛ محافظ اختصاصی تغییرات ذخیره‌نشدهٔ آزمایشگاه نیز حفظ می‌شود. بستن یا تازه‌سازی مرورگر با فرم باز هشدار استاندارد مرورگر دارد. این حفاظت تضمین بازیابی پس از بسته‌شدن اجباری فرایند مرورگر نیست.


### ۷۵ — تطابق مجوز، ورودی و نقش آزمایش؛ اولویت ورود مجدد

در ورود آزمایشی، نقش مدیر یا کاربر عادی انتخاب می‌شود. این انتخاب فقط شبیه‌سازی است و مجوز حساب یا قرارداد ذخیره‌شده را عوض نمی‌کند. در فرم عملیاتی، نقش از حساب احراز‌شدهٔ برنامه به کامپوننت‌ها می‌رسد و فراهم‌کنندهٔ تنظیمات داخلی نباید آن را گم کند. افزودن، ویرایش و حذفِ غیرمجاز باید هم در دکمه و ورودی مخفی یا فقط‌خواندنی باشد و هم در ثبت کنترل شود؛ پیام مجوز از پیام تکرار جداست. جست‌وجو و تغییر پیش‌فرض مطابق مجوز مستقل باقی می‌مانند. در حالت طراحی، اجزای قابل طراحی به‌خاطر نقش آزمایشی مخفی نمی‌شوند. پنجرهٔ ورود مجدد بر پنجرهٔ کامپوننت اولویت دارد؛ نگه‌داشتن فوکوس و کلیک در پنجرهٔ قبلی تا پایان احراز هویت تعلیق می‌شود، بدون حذف متنِ ثبت‌نشدهٔ آن. خطای موقت دریافت حساب نباید کاربر را خارج کند؛ تلاش دوباره بدون بستن برنامه در دسترس است. درخواست ورود هم زمان انتظار محدود و پیام تلاش مجدد دارد. آزمون باید ورود مجدد با کلیک و تایپ واقعی، با کامپوننت باز و متن ثبت‌نشده، را پوشش دهد.

## 76. بازخورد ثبت فهرست و نمایش فشردهٔ CBM

- خطای مجوز، نام تکراری و ورودی ناقص باید از هم مشخص باشند. خطا ورودی و فوکوس را حفظ می‌کند؛ تغییر ورودی پیام و اعتبار نامعتبر قبلی را پاک می‌کند تا ثبت بعدی نیاز به بستن کامپوننت نداشته باشد.
- نام‌های متنی با یکسان‌سازی حروف فارسی/عربی، ارقام و فاصله‌ها بررسی می‌شوند؛ نام موجود دوباره ساخته نمی‌شود و کاربر باید همان مورد موجود را انتخاب کند.
- بسته‌بندی در فیلد بسته فقط «کارتن — ۲٫۷۴» نمایش می‌دهد؛ بدون عبارت مترمکعب/تن، تک‌خطی و بدون تغییر ابعاد فیلد. موارد متعدد داخل همان فهرست مشترک قابل مشاهده‌اند.
- آزمون مرورگری باید رد تکراری و سپس ثبت ورودی اصلاح‌شده، اصلاح ضریب CBM نامعتبر با F3 و ثابت‌ماندن ابعاد فیلد را پوشش دهد.

## 77. اعتبارسنجی بسته‌بندی هنگام ذخیرهٔ کل فرم

- مقدار نمایشی «کارتن — ۲٫۷۴» عدد ساده نیست؛ قواعد عددی فیلد CBM باید روی ضریب عددی هر ردیف جزئیات اجرا شوند، نه روی عنوان نمایشی بسته‌بندی.
- ذخیرهٔ کل فرم، جزئیات واقعی بسته‌بندی و پیش‌فرض را کنترل و همراه رکورد نگه می‌دارد. متن نمایشی بدون جزئیات معتبر برای ثبت کافی نیست.
- هنگام ویرایش رکورد، جزئیات بسته‌بندی همان رکورد بازگردانده می‌شوند؛ اطلاعات رکورد قبلی نباید مبنای ذخیره قرار گیرد.
- آزمون مرورگر باید ذخیرهٔ کل فرم با فیلد CBM دارای نوع عددی و قواعد مثبت/حداقل، پس از ثبت بسته‌بندی اعشاری را پوشش دهد.

## 78. حرکت فیلد، زبان پیش‌فرض و ردیف‌های مرجع بسته‌بندی

## 79. لبهٔ متن، تأیید گزینه با Enter و عرض متناسب CBM

## 81. ارتباط جدول و پنل در کنترل تحویل

- ارتباط جدول با پنل نمایش از ارتباط ستون‌ها با فیلدها جداست. نمایشگر هر دو شکل `table.sectionId` و `section.tableIds` را پشتیبانی می‌کند؛ کنترل تحویل نیز هر دو را برای پنل جدول فعال معتبر می‌داند و نباید وجود هم‌زمان هر دو را الزام کند.
- نبود واقعی پنل، در تنظیمات همان جدول با انتخابگر قرمز «پنل نمایش این جدول» و فوکوس مستقیم روی آن مشخص می‌شود. توضیح فارسی باید محل اصلاح را بگوید؛ شناسهٔ فنی خطا به‌تنهایی پیام قابل استفاده نیست. ستون‌های سالم نباید به‌دروغ خطادار شوند.
- انتخاب پنل فقط ارتباط نمایش جدول را تغییر می‌دهد؛ اتصال ستون‌ها به فیلدها، چیدمان، ظاهر و داده‌ها حفظ می‌شوند. نسخهٔ ۸۱ در خروجی JSON و قرارداد فرم‌های بعدی ثبت است.

- تغییر عرض ستون در جدول مشترک، مستقل از نقش کاربر و نوع منبع داده است. فقط عرض ستون انتخاب‌شده تغییر می‌کند؛ عرض ستون‌های دیگر و فاصلهٔ اسکرول از ابتدای منطقی جدول حفظ می‌شوند. جدول فارسی در سمت راست قرار می‌گیرد، حتی اگر پس از کوچک‌کردن ستون‌ها از پنل باریک‌تر باشد؛ فضای خالی باید در انتهای منطقی باشد. این رفتار برای جدول صفحه‌بندی سرور نیز الزامی است و با قرارداد عملیاتی نسخه ۸۲ صادر می‌شود.

- قرارداد نسخه ۸۳: عنوان‌های ستون در فاصلهٔ کلمات چندخطی می‌شوند، حداقل فضای دو خط دارند و از ارتفاع ذخیره‌شدهٔ هدر استفاده می‌کنند؛ فونت و دکمه‌های فیلتر/مرتب‌سازی حفظ می‌شوند.

- اسکرول عمودی جدول همواره سمت چپ است؛ جهت محتوای جدول مطابق زبان فرم باقی می‌ماند. تغییر عرض ستون همچنان فاصله از ابتدای منطقی را حفظ می‌کند.

- اصلاح قرارداد نسخه ۸۴: شکستن عنوان فقط میان کلمات مجاز است؛ شکستن حروف داخل یک کلمه و خط‌تیره‌گذاری خودکار ممنوع است. محدودیت حداقل دو خط لغو شد؛ ارتفاع دقیق انتخاب‌شدهٔ کاربر رعایت می‌شود و قابل افزایش/کاهش باقی می‌ماند. اگر یک کلمه در عرض ستون جا نشود، کاربر عرض را افزایش می‌دهد؛ عنوان اجازه ندارد ارتفاع هدر را خودکار افزایش دهد.

### حذف گروهی جدول‌های تعریفی — قرارداد ۹۲

- انتخاب پراکنده با Ctrl و انتخاب بازه با Shift؛ Ctrl+Shift بازه را به انتخاب قبلی اضافه می‌کند. بازه بر اساس ترتیب و فیلتر جاری است، حتی بین صفحه‌های دریافت تدریجی؛ حداکثر ۵۰۰ ردیف.
- Delete و دکمه حذف از یک انتخاب استفاده می‌کنند و تعداد دقیق را پیش از حذف می‌پرسند. هنگام ورود اطلاعات و در جدول‌های گزارشی فعال نیست.
- درخواست شامل شناسه پایدار و نسخه هر رکورد است. سرور مجوز، سابقه استفاده، کلیدهای خارجی و تغییر هم‌زمان را کنترل می‌کند؛ همه حذف‌ها در یک تراکنش انجام می‌شود. یک مورد نامعتبر، کل درخواست را برمی‌گرداند. انتخاب باقی می‌ماند و ردیف مانع قرمز می‌شود.
- در نخ، شناسه ردیف رنگ ملاک است؛ انتخاب بخشی از رنگ‌ها فقط همان رنگ‌ها را حذف می‌کند. انتخاب همه رنگ‌های یک نخ، نخ بدون سابقه را حذف می‌کند؛ تأییدیه این تفاوت را بیان می‌کند.
- بارانداز زون حذف نمی‌شود. قفل نشست ویرایش زون حفظ می‌شود. فعلاً چون گردش موجودی شناسه زون ندارد، سابقه موجودی انبار مانع حذف زون است.
- اتصال اجرایی فعلی: نخ، برند طراحی‌شده، اشخاص، گروه کالا، انبار و زون. فرم جدید باید آداپتور حذف دارای مجوز را به جدول مشترک بدهد؛ هیچ گزارش یا جدول دلخواهی خودکار مجوز حذف دریافت نمی‌کند.
- بدون بیلد، آزمون و حذف داده واقعی طبق خواسته کاربر. فعال‌سازی مسیرهای جدید سرور به بیلد و راه‌اندازی مجدد نیاز دارد.

### جلوگیری از انتخاب متن مرورگر — قرارداد ۹۳

انتخاب چند ردیف با Ctrl/Shift باید فقط نشانگر انتخاب خود جدول را فعال کند. جلوگیری از انتخاب متن باید در mousedown انجام شود؛ preventDefault در click دیر است و نمی‌تواند انتخاب آبی مرورگر را متوقف کند. همین محافظ برای انتخاب چند فیلد در طراحی برقرار است. رویداد به انتخاب‌گر خود فرم می‌رسد و فقط رفتار پیش‌فرض مرورگر لغو می‌شود. متن و مکان‌نما داخل کنترل‌های تایپ، از جمله انتخاب کد پیشنهادی و Shift همراه کلید جهت، تغییر نمی‌کند. بیلد و تست بنا به درخواست کاربر اجرا نشد.

### جای نوار انتخاب گروهی — قرارداد ۹۴

تعداد و حذف انتخاب‌ها در فضای مستقل بین سه کلید سمت چپ و عنوان جدول قرار می‌گیرند و روی جست‌وجو نمی‌افتند. فقط انتخاب با Ctrl/Shift آن را نمایان می‌کند؛ انتخاب عادی یا حرکت عادی ردیف‌ها آن را پنهان می‌کند. رهاکردن کلید، انتخاب ایجادشده را از بین نمی‌برد تا دکمه حذف قابل کلیک باشد.

Delete برای ردیف تکی جاری، از جمله پس از حرکت با کلید جهت، نیز فعال است؛ پنهان شدن نوار گروهی آن را غیرفعال نمی‌کند. همان آداپتور و تأییدیهٔ حذف گروهی استفاده می‌شود تا در جدول نخ، حذف یک ردیف رنگ اشتباهاً حذف کل نخ نشود.

### اصلاح نوار انتخاب‌ها — قرارداد ۹۵ (جایگزین چیدمان قرارداد ۹۴)

نوار تعداد/حذف انتخاب‌ها شناور در فضای میانی هدر با قلم خوانای ۱۶ پیکسل است. نمایش یا پنهان شدنش نباید هیچ ستون چیدمان جدیدی ایجاد کند یا عنوان، شمارنده، جست‌وجو و کلیدها را جابه‌جا کند. هم‌پوشانی موقت با محتوای همان ناحیه مجاز است؛ انتخاب عادی آن را پنهان می‌کند.

اصلاح قرارداد ۹۶: دکمهٔ حذف انتخاب‌ها حفظ می‌شود. مجموعه نسبت به جای قبلی حدود دو سانتی‌متر به چپ منتقل می‌شود؛ ظرف بیرونی هیچ کادر، زمینه یا سایه‌ای ندارد و عنوان/شمارنده جابه‌جا نمی‌شود.

اصلاح ظاهری قرارداد ۹۷: نوار نسبت به مرحلهٔ قبل یک سانتی‌متر دیگر به چپ می‌رود (مجموعاً سه سانتی‌متر از جای اولیه) و قلم آن ۲۰ درصد، از ۱۶ به ۱۲٫۸ پیکسل، کوچک‌تر می‌شود.

### جلوگیری از انتخاب کل صفحه با Ctrl+A — قرارداد ۹۸

Ctrl+A با صفحه‌کلید فارسی یا انگلیسی نباید متن کل صفحه، برچسب‌ها یا فیلدهای نمایشی را انتخاب کند؛ حتی اگر تمرکز روی بدنه یا ظرف جدول باشد. تنها داخل کنترل تایپ فعال و قابل ویرایش، انتخاب متن بومی مجاز است. انتخاب منطقی سلول/ردیف جدول و انتخاب فیلدهای طراحی در محل‌های مجاز حفظ می‌شود. محافظ مشترک پس از پردازش انتخاب‌های اختصاصی و پیش از رفتار پیش‌فرض مرورگر اجرا می‌شود. بیلد و تست اجرا نشد.
